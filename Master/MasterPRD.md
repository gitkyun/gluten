# 1. Problem

## 1.1 Fragmented Bakery Exploration

Current bakery exploration behavior is fragmented across:
- Instagram
- Naver Map
- Blogs
- Kakao Map
- Saved screenshots
- Separate bookmark systems

Users constantly lose exploration continuity.

---

## 1.2 Search-first UX Limitation

Traditional map/review platforms prioritize:
- keyword search
- ratings
- utility information

However bakery exploration is often driven by:
- atmosphere
- bread texture
- stay experience
- social discovery
- taste preference
- emotional curiosity

---

## 1.3 Dead Bookmark Problem

Saved places become static bookmarks.

Existing systems fail to support:
- re-exploration
- taste accumulation
- archive-based discovery
- exploration continuity

---

## 1.4 Lack of High-interest Bakery UX

Bakery enthusiasts behave differently from general restaurant users.

Bakery exploration includes:
- bread categories
- sold-out timing
- atmosphere sensitivity
- stay suitability
- local exploration
- collection behavior

Most existing services do not support this behavior deeply.

---

## 20.1 Onboarding Experience

### Goal
신규 유저의 취향을 12-step 흐름 안에서 자연스럽게 수집 + 사업자 분기 지원.

### Flow
```text
Splash (mood orbit dots)
→ Login (이메일 입력)
   ├─ Reset 1 → Reset 2 → Login
   └─ → UserType
       ├─ 일반 유저 → Signup → Taste1 (빵 14종) → Taste2 (분위기 12종) → 앱 진입
       └─ 사업자    → BizSignup → BizStore → BizHome → BizNews → 사업자 앱 진입
```

### Taste Capture
- **빵 취향 (14)**: 소금빵·크루아상·케이크·타르트·마카롱·도넛·식빵·베이글·스콘·휘낭시에·바게트·파이·브리오슈·깜빠뉴
- **분위기 취향 (12)**: 조용한·햇살 좋은·우드톤·미니멀·빈티지·모던·아늑한·루프톱·혼자 오기 좋은·작업하기 좋은·데이트·브런치

### Mood Group 매핑
분위기 12개 → 4 mood key 그룹 (sweet/savory/healthy/specialty)으로 분류.

| Group | Emoji | Label | 분위기 태그 |
|-------|-------|-------|-------------|
| sweet | ☀️ | 따뜻한 | 햇살 좋은 · 아늑한 · 브런치 |
| savory | 🪵 | 빈티지 | 우드톤 · 빈티지 · 혼자 오기 좋은 |
| healthy | 🌿 | 미니멀 | 미니멀 · 조용한 · 작업하기 좋은 |

## 20.11 UX/UI & Navigation Evolution (2026-05-29)

최근 사용자, 디자이너, PM의 종합 피드백에 맞춰 개선된 핵심 UX/UI 시스템 사양.

### 1) 오버레이 중첩 스택 (`overlayStack`) 시스템
* **구조**: 단일 오버레이 상태에서 복수 개의 오버레이를 배열 스택 구조(`overlayStack = []`)로 누적하는 구조로 전면 개편.
* **효과**: 상세 정보(`ScreenDetail`)도 스택으로 통합 처리하여, 오버레이 위에서 상세를 열고 유저 프로필이나 소모임 지도로 크로스 진입하더라도 뒤로 가기(Pop) 시 기존 화면의 스크롤 위치와 상태가 100% 온전히 유지됨.
* **화면 유지**: 5대 메인 탭 화면들을 교체 렌더링이 아닌 DOM 상에 항상 유지시키고 `display` 속성(`none` / `block`)으로만 가시성을 토글하여 탭 전환 간의 스크롤 복원 및 상태 보존 실현.

### 2) 2단계 저장 토스트 알림 및 간편 저장 (Quick Save)
* **흐름**: 탐색 피드나 리스트에서 별표(Star) 클릭 시 즉시 팝업이 뜨며 스크롤을 막는 대신, 기본 폴더(`'c1'`)로 즉시 북마크 처리 후 하단에 **"저장되었습니다 [폴더 변경]"** 샌드박스 토스트 알림을 3초간 띄움.
* **분류**: 토스트 알림 내 [폴더 변경] 단추를 누를 때만 기존의 폴더 분류 시트(`SaveFolderSheet`)를 열어 탐색 리듬을 깨뜨리지 않고 무한 스크롤 및 북마크 축적 가능.

### 3) 탭 기능 분리 및 Near(주변) 실시간 필터 연동
* **Explore 탭 (에디터 픽)**: 중복되던 주변 인기 TOP 8 영역을 삭제하여 매거진 스타일 큐레이션 및 AI 리포트/퀴즈 브랜칭에만 집중.
* **Near 탭 (실시간 주변)**: 상단 카테고리 칩 필터('소금빵', '지금 한가', '크루아상' 등) 클릭 시 지도 상의 마커 핀과 바텀 시트 리스트가 실제 데이터에 맞추어 실시간 필터링 반영. 칩 필터 변동 시 말풍선 초기화 및 헤더 타이틀 갱신("주변 소금빵 3곳").

### 4) 설정 다크 모드 표시 브라우저 동기화
* **테마 동기화**: 설정 스위치 다크모드 On/Off에 따라 HTML 문서 최상위 요소(`document.documentElement`)에 `data-theme="dark"` 속성을 탈부착.
* **디자인**: 유리(Glass) 카드의 틴트, 보더 두께(1px fallback) 및 그림자, SVG 차트 및 Naver-style 도로 미니맵 배경색들을 CSS 변수(`var()`)로 이중화하여 다크 테마 전환 시 전체 화면이 자연스럽게 검은 톤 아크릴 판 테마로 실시간 전환 지원.

### 5) 방사형 차트 레이블 꼭짓점 겹침 방지
* **수식 조정**: 5차원 오각형 차트 꼭짓점 좌표에 따라 `textAnchor` 값을 다르게 분기(`middle`, `start`, `end`)하고 각 텍스트 라인의 X, Y 오프셋을 동적으로 가감하여 모서리 선과의 레이블 겹침 현상을 완벽 차단.

## 20.12 Explore 탭 이중 구조 (에디터 픽 / 실시간 랭킹)

### Goal
단일 콘텐츠 피드를 에디터 큐레이션과 실시간 데이터로 분리해 탐색 의도 다양성 지원.

### Structure
```text
Explore Tab
├─ 에디터 픽 (CurationView)
│   ├─ Editorial hero (featured bakery)
│   └─ Discovery lanes (mood / bread / local / trend)
└─ 실시간 랭킹 (TrendView)
    └─ → RankDetail 오버레이
```

### UX Principle
- 탭 상단 세그먼트 컨트롤 (pill 형태)
- 에디터 픽: 매거진 감성 큐레이션
- 실시간 랭킹: 데이터 기반 현재 트렌드

## 20.14 Taste Quiz 오버레이

### Goal
기존 취향 데이터를 재보정하는 가벼운 퀴즈 경험.

### Trigger
- Profile 탭 → "취향 퀴즈" 진입
- Taste Report 내 "취향 다시 잡기" 버튼

### Structure

- 진행 표시 (상단 progress)

### UX Principle
퀴즈가 아닌 **탐색 미니게임** 느낌 — 부담 없이 가볍게.
